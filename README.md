# negative-keywords-bot

Telegram-бот, который принимает CSV-выгрузку отчёта «Поисковые запросы» из Google Ads
и возвращает готовый список минус-слов, сгруппированный по кампаниям.

## Что это

Минусовка поисковых запросов — регулярная ручная работа: выгрузить отчёт, глазами пройти
сотни строк, выписать мусор, разложить по кампаниям. Бот делает разбор за один заход и
отдаёт результат тремя частями: минус-слова, сомнительные запросы на ручное решение и
отдельный список тех, которые минусовать **нельзя**.

**Бот ничего не меняет в рекламном кабинете.** Он только предлагает — вставляет минус-слова
человек. Google Ads API не используется: вход это CSV, выгруженный руками.

### Главное продуктовое правило

Бот различает два разных «плохо»:

| Что за запрос | Что с ним делать |
|---|---|
| Нерелевантный — человек ищет не то, что вы продаёте | В минус |
| Релевантный, но не конвертит («доставка рядом со мной») | **Не минусовать.** Это вопрос лендинга и ставок |

Минусовка релевантных запросов режет целевой трафик, поэтому такие запросы выносятся
отдельным блоком с явной пометкой. Дополнительно: запрос, по которому были конверсии,
не предлагается в минус никогда — и корень, встречающийся хотя бы в одном конвертящем
запросе, тоже отклоняется.

### Как устроен разбор

1. **Парсер.** Адаптер формата выгрузки: BOM, служебные строки, числа с запятой и
   неразрывным пробелом, русская и английская локали кабинета.
2. **Слой правил, без ИИ.** Словари мусора, чужое гео, бренды конкурентов из профиля,
   метка «расход есть, конверсий нет».
3. **Слой ИИ.** Оставшиеся запросы уходят в модель пакетом. В модель отправляется
   **только текст запроса и профиль проекта** — названия кампаний, групп объявлений и имя
   клиента не отправляются никогда. Без ключа модели бот работает на слое правил и честно
   пишет, что смысловой разбор недоступен.
4. **Сборка.** Свод по корням, а не по фразам: одно слово `free` вместо сорока фраз с ним,
   с числом запросов и суммой расхода по каждому корню. Группировка по кампаниям,
   универсальный мусор — отдельным блоком под общий минус-список аккаунта.

Performance Max выносится в информационный блок без предложений: минусовка там работает иначе.

## Как запустить

### Локально — разбор файла без Telegram

```bash
npm install
node scripts/analyze-local.js sample/search-terms-sample.csv sample/demo-profile.json --out ./out
```

Если в `.env` задан `GEMINI_API_KEY`, локальный прогон использует и смысловой слой;
без ключа отрабатывает только слой правил.

В `sample/` лежит синтетический демо-набор в нейтральной нише: выгрузка того же формата и
профиль проекта к ней. На нём бот проходит полный путь без единого реального аккаунта.

Тесты:

```bash
npm test
```

### Деплой на Vercel

1. Скопируйте `.env.example` в `.env` и заполните — список переменных ниже.
2. Привяжите каталог к проекту Vercel и перенесите переменные:

   ```bash
   npx vercel link
   node scripts/push-env.js production
   ```

   Скрипт читает `.env` и отдаёт значения CLI напрямую: они не попадают ни на
   экран, ни в историю команд. Альтернатива — вписать их руками в
   **Settings → Environment Variables**.
3. Задеплойте:

   ```bash
   npx vercel --prod
   ```

4. Установите вебхук на адрес задеплоенной функции:

   ```bash
   node scripts/set-webhook.js https://<ваш-проект>.vercel.app/api/telegram
   ```

   Токен и секрет скрипт берёт из `.env`, в аргументы командной строки они не
   попадают. Проверить: `node scripts/set-webhook.js --info`. Снять: `--delete`.

> Один бот — один вебхук. `setWebhook` отключит предыдущую интеграцию этого бота, если она была.

> **Deployment Protection в Vercel должна быть выключена для production.** Telegram не умеет
> проходить авторизацию Vercel и будет получать 401 на каждый запрос. В настройках проекта:
> **Settings → Deployment Protection → Vercel Authentication → Only Preview Deployments**.
> Эндпоинт при этом не остаётся открытым: его закрывают секретный заголовок и белый список `chat_id`.

### Работа с ботом

| Команда | Что делает |
|---|---|
| `/newproject [имя]` | Создать профиль проекта — диалог из четырёх вопросов |
| `/projects` | Список профилей и выбор активного |
| `/deleteproject` | Удалить профиль |
| `/cancel` | Прервать диалог |
| `/help` | Справка |

Дальше — просто пришлите боту файл `.csv`.

Выгрузка отчёта: **Google Ads → Кампании → Аналитика → Поисковые запросы → Скачать → CSV**
(именно `CSV`, не «Excel CSV»).

## Как настроить

### Профиль проекта

Настраивается один раз на клиента, четыре поля:

1. **Что продаём** — коротко, на английском (этот текст читает модель).
2. **Чего НЕ делаем** — самое важное поле: «не работаем с физлицами», «не продаём б/у»,
   «только на заказ». От него сильнее всего зависит точность разбора.
3. **География работы** — города и штаты.
4. **Бренды** — свой и конкурентов.

Профили хранятся в Upstash Redis по ключу `profile:<chat_id>:<slug>` и в репозиторий
не попадают. В репозитории лежит только демо-профиль нейтральной ниши.

### Словари

Словарь мусорных запросов — `config/stopwords.en.json`, справочник географии США —
`config/geo-us.json`. Это данные, а не код: пополняются правкой JSON.

У группы в словаре есть два поля, влияющих на поведение:

- `scope`: `account` — универсальный мусор, идёт в общий минус-список аккаунта;
  `campaign` — на уровень кампании.
- `confidence`: `high` — слово идёт в минус-слова; `medium` — запрос уходит на проверку
  модели, а без неё в блок «сомнительные».

### Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | Токен бота из @BotFather |
| `TELEGRAM_WEBHOOK_SECRET` | да | Длинная случайная строка, `openssl rand -hex 32`. Telegram присылает её в заголовке `X-Telegram-Bot-Api-Secret-Token` |
| `ALLOWED_CHAT_IDS` | да | Белый список `chat_id` через запятую. Свой id — у @userinfobot |
| `UPSTASH_REDIS_REST_URL` | да | Upstash Redis, бесплатный тариф |
| `UPSTASH_REDIS_REST_TOKEN` | да | То же |
| `GEMINI_API_KEY` | нет | Ключ Google AI Studio. Без него работает слой правил |
| `GEMINI_MODEL` | нет | Имя модели. По умолчанию быстрая flash-модель текущего поколения |
| `MAX_TERMS_TO_AI` | нет | Сколько запросов уходит в модель за прогон (200) |
| `AI_BATCH_SIZE` | нет | Размер одного пакета к модели (100) |
| `AI_TIMEOUT_MS` | нет | Таймаут вызова модели (45000) |
| `MIN_SPEND_FOR_MONEY_FLAG` | нет | Порог расхода для метки «сливает деньги» (1) |
| `MAX_FILE_BYTES` | нет | Предел размера входного файла (10 МБ) |
| `MAX_CSV_ROWS` | нет | Предел числа строк в CSV (20000) |
| `DIALOG_TTL_SECONDS` | нет | Время жизни незавершённого диалога (900) |
| `UPDATE_DEDUPE_TTL_SECONDS` | нет | Сколько помнить обработанный update (3600) |

Обязательные переменные проверяются при старте: без них функция падает со списком того,
чего не хватает, а не молча работает наполовину.

## Безопасность

- Эндпоинт вебхука публичный, поэтому доступ проверяется дважды: секретным заголовком
  (запрос вообще от Telegram?) и белым списком `chat_id` (этому человеку можно?).
- Секреты только в переменных окружения. `.env` в `.gitignore` с первого коммита.
- Тексты поисковых запросов и содержимое файлов не логируются.
- Реальные выгрузки в репозиторий не попадают: `*.csv` в `.gitignore`, исключения —
  только синтетические `sample/` и `test/fixtures/`.
- Обработанные `update_id` запоминаются в Redis, поэтому повторная доставка от Telegram
  не приводит к повторному разбору файла.

## Ограничения

- **Performance Max не разбирается** — такие строки выносятся отдельным блоком
  без предложений.
- **Часть расхода недоступна для минусовки.** Google скрывает низкочастотные запросы и
  агрегирует их в строку «Другие поисковые запросы». Бот показывает эту сумму отдельно
  и честно пишет, что сделать с ней ничего нельзя.
- Уровень предлагаемой минусовки — кампания, плюс отдельный блок под общий список аккаунта.

## Стек

Node.js (ESM, без сборки) · Vercel Serverless Functions · Upstash Redis ·
Google AI Studio (Gemini) · `csv-parse`. Telegram Bot API вызывается нативным `fetch`.
